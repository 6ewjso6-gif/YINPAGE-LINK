## YINPAGE-LINK v0.18 更新公告

本次修复安全审计 issue #5 / #6：公开 debug 签名密钥导致「同签名覆盖安装」的风险。

### 应用内更新（issue #6）
- 校验判据从「与本机签名一致」改为**内置官方证书白名单**：
  下载包签名必须等于 `CN=YINPAGE-LINK` 证书的 SHA-256，
  镜像/中间人即使替换 APK 也无法伪造该签名
- Release 元数据不再采信镜像返回的 `browser_download_url`：
  `tag_name` 与附件名过严格白名单后，下载地址由本地按官方仓库规则重新拼装
- `.sha256` 附件改为**必填**：缺失、取不到或哈希不符都直接拒绝安装，不再跳过校验
- 识别非官方构建：当前安装包若不是官方签名（debug / 第三方重签名），
  应用内更新直接禁用并提示重新安装官方版本

### 密钥与构建（issue #5）
- 从仓库删除 `.android/debug.keystore`，`.gitignore` 不再放行任何 keystore
- `:module` 的 release 只接受 CI Secrets 注入的私有密钥，缺失时产出 **unsigned**，
  不再回退到 debug 密钥
- `:app` debug 构建改用本机生成的 debug 密钥（`DEBUG_KEYSTORE` 可指定），
  每台机器不同
- README 公布官方发布证书 SHA-256，供安装前自行核验

### ⚠️ 升级注意
- **官方签名版本（v0.17 及之前的 Release 包）**：可直接应用内升级到 v0.18
- **debug 签名版本（`app-debug.apk` 等）**：签名密钥已公开并作废，
  无法通过应用内更新升级。请先卸载旧包，再从 Release 安装官方签名版本
  （卸载会清空应用内保存的设备记录与日志，可先导出诊断日志）
- **LSPosed 模块**：旧模块用已泄露的 debug 密钥签名，同样需要卸载后
  重新安装用你自己的 release 密钥签名的模块

### 版本
- `APP-t-v0.18`（1800018000），可直接覆盖安装 v0.17（同为官方签名）
