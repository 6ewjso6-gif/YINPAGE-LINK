把博客做成纯客户端渲染，最直接的代价不是“慢”，而是**空白**。

浏览器先拿到一个空容器，再下载脚本，再请求数据，再把正文拼出来。中间这段时间，读者看到的是一片白。搜索引擎和 RSS 阅读器看到的，也差不多。

## 构建期把能算的都算完

Markdown 解析、代码高亮、目录生成、摘要提取，这些都不需要等到用户打开页面才做。它们可以在构建时完成，把结果直接写进 HTML。

```js
// 构建时执行一次，而不是每个访客执行一次
const html = marked.parse(markdown);
```

于是交付顺序变了：

1. HTML 先到，标题、正文、导航都在
2. CSS 到，页面成型
3. JavaScript 最后到，只负责搜索、筛选这类真正的交互

## 这不是“不要 JS”

账号、评论、搜索、编辑器仍然需要客户端。区别在于，它们不该拦在正文前面。

判断标准很简单：**关掉 JavaScript，文章还能不能读？** 能，就说明边界是对的。

## 顺带得到的东西

同一份内容源，可以同时生成：

- 页面
- RSS
- Sitemap
- 搜索索引
- 给 AI 抓取工具看的纯文本

不需要为每个消费者维护一套数据。这件事的价值，往往比“快了零点几秒”更大。
